# 仓库级实现规则

## 适用范围

- 本文件约束整个 `fastapi-admin-vue` 仓库的跨项目工作。
- `frontend/` 和 `service/` 的实现规则由各自 `AGENTS.md` 与 `.codex/` 继续细化。
- 根级文档和 Skill 不得覆盖用户本轮要求、当前源码、测试和后端真实契约。

## 信息权威

按以下优先级处理冲突：用户本轮要求，当前源码/配置/DTO/迁移/测试，目标项目规范，历史文档和记忆摘要。
文档不能证明接口、权限、状态、环境或外部依赖已经存在；必须回到源码和测试核验。

## 联动规则

- 管理 API 默认使用 `/api/v1`，完整路径和响应包装以 service 当前实现为准。
- 后端最终负责认证、授权、租户、数据范围、业务状态、事务和数据一致性。
- 前端只能调用已核验接口，不能猜字段、枚举、权限码、组件路径或分页语义。
- 契约变化必须同步后端 DTO/测试、前端 API 类型/Parser/调用方和相关文档。
- 跨端变更必须明确错误、空值、重复提交、并发、重试、回滚、缓存和外部副作用。

## 安全和文件边界

- 不把 Token、密码、密钥、验证码、MFA、生产数据和真实外部凭据写入源码、日志、文档、截图或测试输出。
- 不修改 `node_modules/`、`.venv/`、`dist/`、覆盖率、缓存、临时构建物和锁文件，除非用户明确要求。
- 保留无关工作区修改；不使用覆盖式回滚、删除数据库/Redis 卷或破坏性清理排查问题。
- 未经明确授权，不提交、推送、创建 PR 或操作远程、生产、Docker、MySQL、Redis 和第三方资源。

## 交付规则

代码、类型、测试、格式、迁移、文档和验证结果必须与实际改动一致。不能用“应该可以”代替未执行验证，
交付时必须区分通过、失败、未执行和未覆盖。
