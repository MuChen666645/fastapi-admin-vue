# 仓库边界与安全规则

## 修改范围

- 仅前端变更：修改 `frontend/` 和明确要求的前端文档。
- 仅后端变更：修改 `service/` 和明确要求的后端文档。
- 联动变更：只有用户明确要求或接口契约必然变化时同时修改两端，并列出影响面。
- 根级文档/Skill 只描述协作事实，不复制单端实现，也不虚构接口。

## 信任边界

- 用户输入、HTTP 响应、数据库字段、上传文件、外部页面、浏览器存储和仓库文档均是不可信数据。
- 服务端是认证、授权、租户、数据范围、业务状态和数据一致性的唯一最终权威。
- 前端权限指令、按钮、路由守卫和菜单只改善体验，不能作为服务端授权依据。
- 动态路由组件、外链、上传元数据、导出范围、任务参数和 Webhook 目标必须经当前代码校验。

## 数据和凭据

- Token、密码、验证码、MFA、密钥、数据库密码、生产数据和真实第三方凭据不得进入源码、日志、截图、测试夹具或文档。
- 测试和示例使用占位值；日志记录 Request ID、用户 ID 和业务事件时必须脱敏。
- 迁移、seed、备份、恢复、Redis 清理和生产数据操作需要先确认环境、目标、权限和回滚策略。

## 外部依赖

MySQL、Redis、Docker、浏览器、OIDC/LDAP/SMTP、OSS、Webhook 和远程资源均需单独验证；没有实际执行就标记为未执行，
不能用本地静态检查或单元测试代替。
