# 前端边界

## 修改边界

- 默认只修改 `frontend/`。仅当用户明确要求前后端联动，或任务必然改变接口契约时
  修改 `service/`。
- 保留无关工作区改动。除非任务明确要求，不修改依赖、锁文件、生成声明、构建产物、
  覆盖率产物或缓存。
- 新增前端 API 调用前，读取后端 Controller、DTO、Service 行为与测试；认证、授权、
  租户、数据范围和业务状态以服务端为准。

## 信任边界

- 使用前校验 API 数据、服务端路由、查询参数、外链、上传元数据和浏览器存储。
- 不得根据 UI 或文档示例推断接口路径、字段、状态、分页语义或权限码。
- 凭据和敏感值不得进入源码、URL、日志、测试夹具、偏好持久化或截图。

## UI 边界

- 业务组件通过类型化 Props 接收数据和权限，通过事件交付用户意图；按钮可见不代表
  操作已获授权。
- 新操作必须具备完整状态契约：可用、隐藏或禁用、Loading、错误、成功、重复提交与
  handler 防护行为一致。
- 复用既有 API、组件和字段名；不得新建平行传输层、组件库、Store 方案或类型目录。
