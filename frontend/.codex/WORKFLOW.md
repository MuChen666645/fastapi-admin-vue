# 前端交付流程

1. 执行 `git status --short` 并保留无关改动。
2. 读取适用规则、源码、调用方、类型、测试和真实后端契约。
3. 在编辑前明确请求、响应、错误、权限、租户行为、Loading、导航和状态清理。
4. 以现有 API、Parser、Store、组件和路由边界实现最小改动。
5. 在变更行为边界补充或更新测试；不得用静态文案或演示断言填充覆盖率。
6. 执行聚焦测试、`pnpm run check` 和 `git diff --check`；影响运行时打包时执行生产构建。
7. 复查接口漂移、权限与 handler 一致性、敏感数据、生成文件和文档事实。

前后端联动时，先记录方法、路径、请求、响应、错误、认证、权限、租户或数据范围，
以及回滚与重试影响，再修改任一端。
