# 代码评审检查表

## 认证和授权

- [ ] 每个敏感读取和写入有后端认证、权限、租户和数据范围检查。
- [ ] 单条、批量、导入、重置、关联、后台任务和运维路径没有旁路。
- [ ] 管理员角色使用配置值，资源不存在与无权限没有混淆。

## 数据和事务

- [ ] HTTP 业务使用请求级 `request.state.mysql`。
- [ ] 审计、Worker、Scheduler 和独立任务使用独立会话。
- [ ] commit、rollback、flush、锁、幂等和重复提交行为有证据。
- [ ] DAO 没有承担 HTTP 语义或绕过 Service 授权。

## API 和运行时

- [ ] 路由使用 `/api/v1`，静态路由位于动态路由之前。
- [ ] DTO、分页、错误、响应包装、文件/流响应和前端实际调用一致。
- [ ] Redis、MySQL、配置导入、生命周期 Task 和健康检查行为有测试或运行证据。

## 数据库和安全数据

- [ ] schema 变化有迁移、离线 SQL 和必要的 seed。
- [ ] 外键、主键、索引和幂等 DDL 顺序安全。
- [ ] 日志和测试没有原始 Token、密码、验证码、密钥或生产数据。

## 结论质量

- [ ] 发现有真实代码路径、影响和严重性。
- [ ] 未验证内容明确标注为风险，而不是已确认缺陷。
- [ ] 评审没有修改工作区或回滚用户变更。
