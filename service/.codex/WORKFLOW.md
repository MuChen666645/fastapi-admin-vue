# 后端交付流程

1. 记录工作区状态，读取关联源码、DTO、Service、DAO、Controller 依赖、迁移、配置和测试。
2. 编辑前明确输入、输出、错误、授权、租户或数据范围、事务、重试、可观测性和运维影响。
3. 以 Controller -> Service -> DAO 分层实现最小改动。
4. 增加聚焦契约或回归测试；保留安全、授权、租户、迁移、生命周期、响应和运维失败路径
   测试，仅清理无实质行为价值的测试。
5. 先运行最小 pytest；共享行为变更时运行完整测试、编译和 `git diff --check`。
6. 涉及迁移时执行 `poetry run alembic upgrade head --sql`、审阅 SQL，并明确报告是否执行了
   真实数据库升级。
7. 交付前复查敏感数据、N+1、事务处理、重试安全、缓存失效、响应漂移和生成物。

本地单元测试不能证明 MySQL、Redis、Docker、OIDC、LDAP、SMTP、浏览器或生产环境已
验证；未执行的外部验证必须如实报告。
